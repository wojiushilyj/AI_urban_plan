## 1. 铁律（AI 必读，违反即回滚）

### 1.1 开工前必做
1. **先读本文件**（`README.md`）。
2. **再读进度文件** `docs/PROGRESS.md`，确认当前阶段与"当前阻塞点"。
3. 读 `docs/SCENARIOS.md` 了解场景定义，读 `docs/COMPETITION.md` 了解评分口径。
4. 三份文件读完前，**不允许新建、修改、删除任何代码文件**。

### 1.2 不可逾越的红线
- **不得擅自更换技术栈。** 技术栈变更必须先在本文件或 `docs/PROGRESS.md` 记录理由，并经项目负责人确认。
- **不得删除他人已提交的模块。** 重构前先在 PR/commit message 说明理由。
- **不得把原始空间数据、涉密数据、个人信息提交进 Git。** `data/raw/`、`data/processed/`、`*.gdb`、`*.shp` 大文件一律在 `.gitignore` 中。
- **坐标系必须显式声明。** 见 §4。不允许出现"不知道这份数据是什么坐标系"就入库的情况。
- **不得编造数据。** 演示数据若非真实来源，必须在文件/文档中明确标注 `样例数据 / SAMPLE`，**申报书中不得把样例数据说成真实数据**（声明第 1、2 条，虚假即取消资格）。
- **不得引入需要付费 Key 才能跑起来的核心链路。** 地图/GIS 服务必须有可离线或免费额度的降级方案，评委复现时不能卡在 Key 上。
- **AI 生成的代码必须有可运行验证。** 后端改动至少 `uvicorn` 起得来、接口能 `curl` 通；前端改动至少 `npm run build` 过。

### 1.3 收尾必做
每次完成一轮工作，**必须更新 `docs/PROGRESS.md`**（改了什么、当前状态、下一步）。不更新的提交视为无效工作。

## 2. 技术栈（固定，不得随意变更）

```
┌─────────────────────────────────────────────────────────┐
│  前端层   Vue 3 + Vite + TypeScript                      │
│           GIS API: MapLibre GL JS（开源）                 │
│           底图: 天地图 OGC WMTS / OSM 栅格（可切换降级）   │
│           图表: ECharts ｜ UI: Element Plus              │
├─────────────────────────────────────────────────────────┤
│  服务层   FastAPI（Python 3.11+）+ Uvicorn               │
│           空间分析: GeoPandas / Shapely / PyProj         │
│           栅格: rasterio  ｜ 数值: numpy / pandas        │
│           AI: 规则推理引擎 + LLM（报告生成/因子解释）     │
├─────────────────────────────────────────────────────────┤
│  数据层   SQLite（+ SpatiaLite 扩展，可选）               │
│           矢量交换格式: GeoJSON（入库/出图统一）          │
│           配置与元数据: SQLite 表 + YAML                  │
└─────────────────────────────────────────────────────────┘
```

- **"小型本地数据库" = SQLite**，不引 Docker / PostGIS，保证评委"拷走就能跑"。
- 若空间 SQL 需求超出 SQLite 能力，**优先用 GeoPandas 在内存算，再把结果写回 SQLite**，而不是上 PostGIS。
- LLM 为**可选增强**：无 Key 时系统必须能用规则引擎跑通全流程并出报告（降级开关 `LLM_ENABLED=false`）。

### 依赖版本锁定原则
- 后端依赖写入 `backend/requirements.txt`，**带下限不带上限**（如 `fastapi>=0.110`），新增依赖必须注明用途。
- 前端依赖写入 `frontend/package.json`。禁止无理由引入重型 UI 框架。

## 4. 空间数据规范（国土行业硬要求）

| 项 | 规定 |
|---|---|
| 存储坐标系 | **CGCS2000  geographic  → EPSG:4490**（国土空间规划法定坐标系） |
| 投影坐标系 | **CGCS2000 / 3-degree Gauss-Kruger CM 108E → EPSG:4545**（广西适用），面积量算必须在此投影下 |
| Web 展示 | 前端渲染用 **EPSG:3857**（Web Mercator），由 MapLibre 自动转换 |
| 单位 | 距离一律**米**，面积一律**平方米/公顷**，禁止"度"参与量算 |
| 精度 | 矢量坐标保留 6 位小数（度）或 2 位小数（米） |

- 任何入库数据必须在 `data/README.md` 登记：文件名、来源、坐标系、时点、是否样例数据。
- 涉"问题地图"红线：**必须使用符合国家标准的底图与界线**，禁用未经审核的境外边界数据。

## 5. 场景与功能边界（详见 docs/SCENARIOS.md）

面向**要素保障 / 格局优化 / 耕地保护 / 矿业发展 / 生态修复**五类需求，系统提供统一的"多场景选址引擎"：

1. **约束叠加**：永久基本农田、生态保护红线、城镇开发边界、河湖管理范围、地质灾害点等禁建/限建图层做布尔与缓冲叠加。
2. **多因子适宜性评价**：AHP 主观权重 + 熵权法客观权重组合，输出 0–100 适宜性栅格/网格。
3. **候选地块生成**：网格化 → 约束过滤 → 连通聚类 → 面积/形状筛选 → Top-N 排序。
4. **AI 论证报告**：LLM 将结构化结果转写为《选址论证报告》/《选址比选意见》，人工可编辑。
5. **一张图可视化**：图层管理、因子权重实时调参、方案对比、成果导出（GeoJSON/图片）。

**范围冻结**：除上述 5 项外的新功能，一律先记入 `docs/PROGRESS.md` 的"待定池"，9-14 前不实现。
